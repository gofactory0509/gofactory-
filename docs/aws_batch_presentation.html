# 왜 새벽인가?
- 면접 트래픽 최저 (학습자 대부분 취침)
- 데이터 소스 응답성 최상 (네이버·DART 한산)
- Fargate Spot 가용성 ↑

왜 일요일인가?

  • 주간 단위 트렌드가 가장 안정적으로 정착되는 시점
  • 월요일 면접 사용자에게 신선한 데이터 제공
  • 주말 동안 누적된 공시·뉴스를 한 번에 흡수
  • 실패 시 평일 영업 시간 내 복구 가능
DeadLetter Queue (SQS): EventBridge가 Batch에 못 전달했을 때의 이벤트를 보관 — 재처리 가능.

AWS Batch — Fargate Spot으로 운영비 70% 절감

Job Definition

항목값
vCPU1
Memory2,048 MiB (2GB)
PlatformFARGATE
NetworkAWS_VPC (public subnet)
Log driverawslogs (/aws/batch/job)
Retry2회 (지수 백오프)

왜 Fargate Spot?

  • On-demand 대비 ~70% 할인 ($0.04/vCPU-hr)
  • 중단 가능성 있지만 우리 job은 멱등 + 재시도
  • EC2 인스턴스 직접 관리 부담 0
  • 5분 후 자동 종료 — 자원 낭비 없음
Secrets Manager로 NAVER·DART 키 주입 → 컨테이너 env 변수에 평문 안 남김.

크롤러 컨테이너 — 3개 소스 + LLM 요약

데이터 파이프라인 (회사당 5초)

  1. 네이버 뉴스 — 최근 7일, 상위 10건 raw text

IAM — 최소 권한 원칙으로 3개 Role 분리

Batch Job Role

컨테이너 내부가 사용

  • bedrock:InvokeModel
  • s3:PutObject (스냅샷 저장)
  • secretsmanager:GetSecretValue
  • logs:PutLogEvents

Batch Execution Role

Fargate가 컨테이너 띄우기 위해 사용

  • ecr:GetAuthorizationToken
  • ecr:BatchGetImage
  • logs:CreateLogStream

EventBridge Role

스케줄러가 Batch submit 호출

  • batch:SubmitJob
  • 대상: 특정 Job Queue ARN만
Defense in depth — 컨테이너가 털려도 외부 시스템 권한이 분리돼있어 피해 영역 한정. Secrets는 평문 노출 없이 SDK 호출 시점에만 메모리에.

비용 최적화 결정

  • Public subnet + assignPublicIp으로 NAT Gateway($32/월) 회피
  • Fargate Spot으로 컴퓨트 비용 70% 감축
  • Haiku 모델 선택 — 요약 품질 충분, Sonnet 대비 80% 저렴
  • S3 스냅샷 보관은 1년만, IA Storage Class로 자동 전환
학생 크레딧 $100이면 ~5.4년 운영 가능. 발표 시점 기준 비용 부담 사실상 0.

모니터링 — 실패 시 즉시 알림 + 재처리

3중 안전망

  • Job-level retry: Batch가 실패 시 2회 자동 재시도
  • CloudWatch Logs: stdout/stderr 영구 보관, Insights 쿼리
  • CloudWatch Alarm: 최근 7일 실패 ≥ 1회 → SNS
  • SNS → 이메일: 운영자에게 실시간 통지
  • EventBridge DLQ: 트리거 자체 실패도 보관

SLO·운영 지표

지표목표
주간 성공률≥ 99%
완료 시간 (5개사)≤ 7분
회사당 데이터 신선도≤ 7일
실패 알림 latency≤ 5분
인적 개입 빈도월 0회
